# Локальный HTTP-API L-Phone

Для интеграции с CRM (1С, Битрикс24, amoCRM, самописные системы): звонок по клику из
карточки клиента и опрос состояния телефона.

Появился 4 августа 2026. До него интеграция была возможна только через
`L-Phone.exe tel:<номер>` — то есть запуском процесса на каждый звонок и без всякого
ответа о том, получилось ли.

---

## Включение

Настройки → **Дополнительно** → **Интеграция с CRM**.

По умолчанию API **выключен**. Это сознательно: функция умеет звонить с вашего телефона,
и включаться сама она не должна.

При включении генерируется **токен** — 32 символа, которые надо вставить в настройки CRM.
Кнопка «Обновить» выдаёт новый; старый перестаёт работать немедленно (это и есть способ
отозвать доступ, если токен утёк).

Порт по умолчанию **8712**. Менять стоит, только если он занят другой программой —
тогда в журнале приложения будет строка `Локальный API: порт 8712 занять не удалось`.

---

## Безопасность

Три правила, на которых всё держится:

1. **Слушаем только `127.0.0.1`.** С других машин API недоступен физически — не «закрыт
   паролем», а просто не принимает соединения. Проверено: запрос на `192.168.x.x:8712`
   не доходит.
2. **Токен обязателен для каждого запроса, включая `/status`.** Без этого любая открытая
   в браузере страница могла бы вставить `<img src="http://127.0.0.1:8712/call?number=...">`
   и позвонить куда угодно от вашего имени. Проверка `/status` тоже закрыта: иначе
   посторонний сайт узнавал бы, что на машине стоит софтфон и под каким номером человек
   зарегистрирован.
3. **Заголовок `Access-Control-Allow-Origin` не отдаётся.** Даже зная токен, страница в
   браузере не сможет прочитать ответ.

Токен передаётся либо параметром `token=`, либо заголовком `X-Token`. Второй способ лучше:
параметр оседает в логах прокси и в истории браузера.

## Команды

Все ответы — JSON, UTF-8. Методы `GET` и `POST` равнозначны.

### `GET /status`

```
http://127.0.0.1:8712/status?token=ВАШ_ТОКЕН
```

```json
{"registered":true,"account":"377","state":"idle","version":"1.2.0"}
```

| Поле | Значение |
|---|---|
| `registered` | зарегистрирован ли на АТС |
| `account` | логин учётной записи |
| `state` | `idle` — свободен, `ringing` — входящий звонит, `incall` — разговор |
| `version` | версия клиента |

### `POST /call?number=<номер>`

```
http://127.0.0.1:8712/call?number=1001&token=ВАШ_ТОКЕН
```

```json
{"ok":true,"number":"377"}
```

Номер можно передавать в любом виде, который принимает набор: `377`, `+79993770000`,
`89993770000`. **Плюс в URL обязательно кодировать** как `%2B`, иначе он превратится
в пробел и номер станет междугородним не тем.

Ответы:

| Код | Когда |
|---|---|
| `200` | звонок начат |
| `400` | `number` не передан |
| `401` | нет токена или он неверный |
| `409` | линия занята — идёт другой разговор |

`409` — не ошибка интеграции, а защита: сбросить чужой разговор «по просьбе CRM» было бы
худшим из возможных сюрпризов. Дождитесь `state: idle` в `/status`.

### `POST /hangup`

Завершает текущий разговор или отклоняет входящий. `{"ok":false}` — завершать было нечего.

### `POST /answer`

Принимает входящий. `{"ok":false}` — входящего нет.

## Примеры

**curl**

```bash
curl "http://127.0.0.1:8712/call?number=%2B79993770000" -H "X-Token: ВАШ_ТОКЕН"
```

**PowerShell**

```powershell
$t = "ВАШ_ТОКЕН"
Invoke-RestMethod "http://127.0.0.1:8712/status" -Headers @{ "X-Token" = $t }
Invoke-RestMethod "http://127.0.0.1:8712/call?number=1001" -Headers @{ "X-Token" = $t }
```

**1С (обычные формы)**

```bsl
HTTP = Новый HTTPСоединение("127.0.0.1", 8712);
Запрос = Новый HTTPЗапрос("/call?number=" + КодироватьСтроку(Номер, СпособКодированияСтроки.КодировкаURL));
Запрос.Заголовки.Вставить("X-Token", Токен);
Ответ = HTTP.Получить(Запрос);
```

**Веб-страница CRM** — обычная ссылка, если токен вы готовы держать в разметке:

```html
<a href="http://127.0.0.1:8712/call?number=1001&token=ВАШ_ТОКЕН">Позвонить</a>
```

Ответ страница не прочитает (CORS закрыт), но звонок уйдёт.

## События в обратную сторону (CRM-хук)

Настройки → **Дополнительно** → **Ссылка на карточку клиента**.

Клиент сам дёргает вашу ссылку на событиях звонка. Два режима:

- **Открывать в браузере** (по умолчанию) — карточка клиента всплывает у оператора ДО того,
  как он снял трубку. Открываются только `http://` и `https://`.
- **Тихий запрос** — обычный GET в фоне, ответ не показывается. Для передачи данных
  в CRM без окон.

Подстановки в шаблоне:

| Плейсхолдер | Значение |
|---|---|
| `{number}` | номер собеседника без домена (`377`, `+79993770000`) |
| `{name}` | имя из адресной книги, если нашлось |
| `{event}` | `incoming`, `outgoing`, `answered`, `ended` |
| `{direction}` | `in` или `out` |
| `{duration}` | длительность в секундах (осмысленна на `ended`) |
| `{callid}` | Call-ID для склейки событий одного звонка |

Все значения кодируются для URL. Неизвестная подстановка остаётся в ссылке как есть —
это опечатка, и прятать её мы не будем.

Пример: `https://crm.example.com/card?phone={number}&ev={event}`

Событий приходит по одному на звонок: `answered` не повторяется после удержания,
`ended` не дублируется парой End/Released. У `outgoing` поле `{callid}` пустое — на момент
начала набора АТС его ещё не назначила; склеивайте по номеру либо по последующим событиям.

Переключатель **«Только на входящие»** оставляет одно событие `incoming` — обычно этого
и достаточно для всплывающей карточки.

### Прокси

Если на машине включён системный прокси (VPN-клиент, корпоративный шлюз), .NET по умолчанию
гонит через него **всё**, включая запросы на `127.0.0.1` — список исключений Windows при этом
не помогает (проверено). Поэтому клиент сам обходит прокси для петли, приватных сетей
(10/8, 172.16/12, 192.168/16, 169.254/16) и коротких имён хостов без домена. Наружу прокси
по-прежнему используется. То же исправление применено к телефонной книге и presence-хуку.

- Управления удержанием, переводом и конференцией.
- Нескольких одновременных линий: `/call` работает, только когда телефон свободен.

Если для интеграции нужно что-то из этого — скажите, добавим.
