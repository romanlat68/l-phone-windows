# Подпись кода L-Phone

Подход тот же, что у Android-версии: подписываем **своим** сертификатом, а доверие обеспечиваем
раздачей его открытой части на машины. У Android это keystore, который никто снаружи не проверяет;
здесь — самоподписанный сертификат подписи кода, заранее внесённый в доверенные.

## Что это даёт и чего не даёт

**Даёт.** Внутри организации, где сертификат роздан групповой политикой:
установщик и `L-Phone.exe` подписаны, Windows показывает издателя вместо «Неизвестный издатель»,
SmartScreen и UAC ведут себя спокойно, а подмена файла ломает подпись и видна.

**Не даёт.** Постороннему пользователю, скачавшему установщик из интернета, SmartScreen всё равно
покажет предупреждение: репутацию даёт только сертификат публичного УЦ (OV/EV). Для продажи наружу
понадобится покупной — менять придётся ровно одну переменную `LPHONE_SIGN_PFX`, весь остальной
конвейер уже готов.

## Ключ уже есть — тот же, что у Android

Отдельный сертификат для Windows создавать не нужно: подходит релизный keystore
Android-версии `%USERPROFILE%\lphone-keys\lphone-release.jks`. Проверено 2026-07-30:

| свойство | значение | почему годится |
|---|---|---|
| тип хранилища | **PKCS12** | формат, который `signtool` принимает как есть; расширение `.jks` не мешает |
| владелец | `CN=L-Phone, O=L-Phone, C=RU` | Windows покажет издателем «L-Phone» — ровно то, ради чего подпись и нужна |
| ключ | RSA 2048, SHA384withRSA, до 07.12.2053 | Authenticode поддерживает |
| расширения | только SubjectKeyIdentifier, **EKU нет** | сертификат без EKU Windows считает годным для всех назначений, включая подпись кода |

Задать переменные окружения (они и включают подпись при сборке):

```powershell
setx LPHONE_SIGN_PFX  "%USERPROFILE%\lphone-keys\lphone-release.jks"
setx LPHONE_SIGN_PASS "<пароль от keystore>"
```

Один ключ на обе платформы — это осознанный выбор в пользу простоты: одна личность продукта,
один `.cer` для раздачи. Обратная сторона — общая зона поражения: утечка с любой сборочной
машины компрометирует и APK, и Windows-сборки. Когда появится покупной сертификат для Windows,
платформы разойдутся сами собой (у Android ключ должен жить десятилетиями, у покупного срок
1–3 года), и это нормально.

### Если ключа нет (новая установка, другая машина)

```powershell
powershell -ExecutionPolicy Bypass -File tools\new-signing-cert.ps1
```

Скрипт спросит пароль и создаст `.pfx` (закрытый ключ, **не коммитить**) и `.cer`
(открытая часть, раздавать на машины) в `%USERPROFILE%\.lphone\`.

### Выгрузить открытую часть из существующего keystore

Для раздачи доверия нужен `.cer`; из PKCS12 он достаётся так:

```powershell
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" `
    -exportcert -rfc -alias lphone `
    -keystore %USERPROFILE%\lphone-keys\lphone-release.jks `
    -file lphone.cer
```

Переменные не заданы — `build-installer.ps1` собирает как раньше и предупреждает, что подпись
пропущена. Сборка не ломается.

## Каждая сборка

```powershell
powershell -ExecutionPolicy Bypass -File build-installer.ps1
```

Подписывается `dist\L-Phone.exe` **до** упаковки (установщик несёт exe внутри, потом уже не
подписать), затем сам `installer\L-Phone-Setup-*.exe`.

Подпись ставится с меткой времени RFC 3161 (`/tr`, DigiCert с запасным Sectigo). Без метки подпись
перестала бы считаться действительной вместе с истечением сертификата; с меткой остаётся
действительной и после.

Проверить результат:

```powershell
& "${env:ProgramFiles(x86)}\Windows Kits\10\bin\10.0.26100.0\x64\signtool.exe" verify /pa /v installer\L-Phone-Setup-1.0.exe
```

На машине, где сертификат ещё не роздан, `verify` сообщит о недоверенной цепочке — это ожидаемо
и означает ровно то, что следующий шаг не выполнен.

## Раздать доверие на машины

Сертификат нужно положить в **два** хранилища локального компьютера: «Доверенные корневые центры
сертификации» (иначе цепочка не строится) и «Доверенные издатели» (иначе Windows всё равно
переспрашивает).

Разово на одной машине, от администратора:

```powershell
Import-Certificate -FilePath code-signing.cer -CertStoreLocation Cert:\LocalMachine\Root
Import-Certificate -FilePath code-signing.cer -CertStoreLocation Cert:\LocalMachine\TrustedPublisher
```

В домене — групповой политикой:
`Конфигурация компьютера → Политики → Конфигурация Windows → Параметры безопасности →
Политики открытого ключа` → в «Доверенные корневые центры сертификации» и «Доверенные издатели»
импортировать `code-signing.cer`.

## Когда появится покупной сертификат

1. Получить `.pfx` от УЦ.
2. Переставить `LPHONE_SIGN_PFX` и `LPHONE_SIGN_PASS` на него.
3. Всё. Скрипт сборки, метки времени и порядок подписи не меняются, а раздача своего `.cer`
   на машины становится не нужна.

## Чего ещё нет

Автообновления. Подпись — его обязательное условие (обновление должно проверять, что пришло от
нас), но сам механизм доставки не сделан.
